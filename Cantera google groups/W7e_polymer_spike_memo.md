# W7e — Polymer-generation spike: go/no-go memo (P12)

**Date:** 2026-07-20 · **Status:** spike delivered (memo, not a generator —
exactly as the W7 plan scoped it). **Recommendation: conditional GO,
narrowly scoped** (details in §4).

## 1. What P12 actually asks

Two independent community threads want RMG-style automatic generation for
polyethylene (PE) pyrolysis — i.e. broad-product distributions from a
polymer feedstock — and both stalled the same way: naive RMG runs on a long
alkane surrogate explode combinatorially (edge growth ~exponential in carbon
count) or never terminate (P30). This is a genuine research problem, not a
missing switch.

## 2. What this suite already has that bears on it

- **Finite-solid reactor (W5a, shipped)** — the *physical* half of PE
  pyrolysis (a depleting condensed feedstock feeding gas-phase products) is
  now representable: `FiniteSolidReactor` with a `constant_area` or custom
  area model is the right harness for a lumped "molten PE" bulk phase with
  surface/interfacial release reactions. This did not exist when P12 was
  raised.
- **Supervisor (W7b, shipped)** — the runaway-generation failure mode that
  killed the community attempts is now bounded: memory budget, stall
  detection, staged conditions, tolerance relaxation. Any generation
  experiment can be run to a *report* instead of a hung machine.
- **Family-completeness scan + targeted graft (#2, shipped)** — the
  machinery to ask "which reaction families does a mechanism lack for
  species class X?" and to graft targeted additions is the natural carrier
  for a *lumped-family* approach: recurring β-scission + H-abstraction +
  radical-recombination templates applied to a homologous series, with
  products lumped by carbon count.
- **Explainer (W7a, shipped)** — makes the edge inspectable, so a spike run
  can *show* where the combinatorial explosion happens instead of guessing.

## 3. The technical crux (why naive RMG cannot do this)

1. **Species representation.** RMG species are explicit molecular graphs;
   PE is effectively C~10^4+. Any faithful representation is out. Every
   viable route goes through a **surrogate + lumping** layer: represent the
   melt as a short homologous series (C20–C40 alkane + mid-chain radicals),
   and lump products by (carbon count, family) rather than isomer.
2. **Family closure, not discovery.** PE pyrolysis chemistry is dominated by
   four recurring families (random-scission initiation, mid-chain
   H-abstraction, β-scission propagation "unzipping", radical
   recombination/disproportionation). The chemistry is *known*; the problem
   is enumerating it compactly — a template/lumping problem, which is what
   the #2 family-scan machinery does, not an exploratory-flux problem, which
   is what RMG does.
3. **RMG's role shrinks to a kinetics oracle**: rate rules for the four
   families on representative small-molecule analogues, queried through the
   existing `reaction_family_kb` subprocess bridge — not whole-model
   generation.

## 4. Recommendation: conditional GO, scoped as follows

**GO** on a *lumped homologous-series generator* built on suite-local
machinery (est. M effort):
- surrogate series C_n H_{2n+2} (n = 4…N, N ≈ 30) + mid-chain radicals,
  generated by template (β-scission / H-abstraction / recombination), with
  per-carbon-count lumping — a deterministic enumeration, no flux-driven
  edge, so it terminates by construction;
- rates from Arrhenius rules per family (literature values as defaults;
  RMG rate rules as an upgrade when the env exists);
- coupled to `FiniteSolidReactor` for the melt→gas physics;
- validated against published PE-pyrolysis product distributions (gas yield,
  C1–C4 vs wax split vs T).

**NO-GO** on using RMG's own exploratory generation for the polymer itself,
even supervised — the edge explosion is structural (isomer count), not a
tuning problem. The supervisor makes the failure *bounded and reported*, not
absent.

**Env-gated checks before committing the GO** (need the RMG env, absent on
this machine as of this memo):
1. Confirm RMG rate-rule queries for mid-chain C15+ radicals return in
   seconds (they are graph-isomorphism-bound) via `reaction_family_kb`.
2. One supervised RMG run on n-C16 pyrolysis with `--mem-gb 8 --stall-timeout
   1800` to quantify where the edge explodes (using `rmg-explain` on the
   result) — this calibrates the surrogate-length choice N.

If (1) fails, fall back to literature rate rules only — the GO stands, with
lower kinetics fidelity. If (2) shows n-C16 is tractable, N can be raised.

## 5. Decision requested

Approve the scoped GO above as a future workstream (it is *not* part of W7
delivery), or park P12 with this memo as the recorded analysis.

## 6. Decision: DEFER (2026-07-22)

The conditional GO in §4 stands — it is not rejected. Building it now is
deferred, for two reasons:

1. **No current consumer.** Nothing in this suite or in the active Ammonia
   campaign needs polyethylene-pyrolysis chemistry; the demand is two
   external Cantera-community threads, not an internal pipeline.
2. **It is env-gated on infrastructure this machine doesn't have.** Both
   pre-commit checks in §4 need the RMG env (absent — see
   `MarkDownFiles/PENDING_2026-07-21.md`'s targeted-RMG-generation notes:
   RMG-Py present but not Cython-built, no `rmg_env` interpreter, no
   RMG-database on disk). Building against the untested literature-rate
   fallback risks reworking the surrogate-length calibration once that env
   exists anyway.

**Re-open this when:** a real user/project needs polyolefin-pyrolysis
chemistry, or the RMG env gets stood up for the targeted-generation live
path (see `reaction_family_kb.py`'s "Activating the live RMG backend"
section) — the same env unblocks both, so standing it up for one is a
natural trigger to revisit the other. Until then, no further work planned;
the design in §3-4 remains the recorded starting point.
